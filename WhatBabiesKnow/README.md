# WhatBabiesKnow

The infant watches short videos covering gaze following, object representation,
relations, action prediction, geometry, and numerosity, with attention grabbers
included throughout the session.

Run from the repository root: `pixi run what-babies-know`.

## Study structure

**3 blocks × 18 video presentations = 54 presentations per session.**

**Block 1 → Break → Block 2 → Break → Block 3**

Each block includes all the groups below. **Group order is shuffled, but videos
within a group stay together**—the individual videos are not all intermixed.
Participant setup and optional eye-tracker positioning/calibration happen before
the start screen; data are saved after each block and at the end.

| Task group | Videos per block |
| --- | ---: |
| GazeFollowing | 3 |
| ObjectRepresentation | 2 |
| Relations | 2: one Neutral + one Violation |
| ActionPrediction | 2 |
| Numerosity—easy | 2 |
| Numerosity—hard | 2 |
| Geometry | 2 |
| Attention grabbers | 3: three separate groups, one clip each |
| **Total** | **18** |

**Video time:** approximately **3 min 13 s per block**, or **9 min 40 s overall**.
Allow extra time for the 250 ms block-start intervals, setup/calibration, loading,
and operator-controlled breaks.
Every video plays to its end. A **250 ms background-matched wait** is added before the next
video within a block, after gaze saving and any requested pause. Actual gaps
also include saving/rendering time. The 51 waits add 12.75 s to a full session;
none is added after a block's final video. This is an addition to the Tobii design.
The interval is white after GazeFollowing, Numerosity and Geometry,
and black after other tasks. Requested pauses/breaks replace this plain screen.

## Randomization

- Group order and the selection/order of videos within groups are randomized
  for each block. Numerosity easy and hard are separate groups.
- GazeFollowing, ActionPrediction, Geometry, and each Relations subgroup draw
  without replacement: unused videos carry across blocks until the pool is empty.
- ObjectRepresentation and both Numerosity groups allow repeated selections,
  including the same video twice within a block.
- Relations selects Neutral and Violation independently, then randomizes their order.
- The three attention groups are shuffled alongside the tasks. Attention clips
  can occur consecutively, and the same clip can be selected by different groups.

Orders for S001–S400 are saved in `Stimuli/sequences.csv`; playback follows the
assigned order without further randomization. Keep these schedules unchanged
during data collection. They are generated by `Stimuli/generate_sequences.py`.
These rules follow the saved Tobii design and documented sampling behaviour;
exact equivalence to the Tobii runtime has not been tested.

## Presentation and controls

All videos are centered. Relations is enlarged proportionally to **1920 × 1080**;
all other videos retain their native size. The source files are unchanged.
Relations movies play for approximately **35 s**, despite `_5s` in their filenames.
GazeFollowing's gray surround switches to white at the displayed frame timestamp
of **8 s**, matching the final **500 ms** of all 64 clips. Geometry and Numerosity
use white surrounds. Relations uses a black surround and a black interval.
Video files and durations are unchanged.

- **Space:** start from the opening screen, or continue from a pause/between-block break.
- **Esc during playback:** finish the current video, then show the pause screen.
  There, Space continues and Esc stops. Esc on the opening screen aborts.
- **X during playback:** finish the current video, then loop an extra video break
  (`utils/pause.avi`). Press X again to continue. This is additional to the
  scheduled attention clips and is not included in the 54 presentations.

Between blocks, the screen stays black while the next block is prepared, then
waits for Space. Breaks have no fixed duration. Optional gaze and webcam recording
start before block 1 and continue through pauses and breaks.

## Events / triggers

These are **named software events**, not hardware TTL pulses. They are saved in
the JSON and sent to eye tracking/webcam recording when enabled.

| Event | When it is emitted |
| --- | --- |
| `study_start` | After optional recording starts, just before the block loop. |
| `block_start` | After preparation and any between-block pause, followed by 250 ms on black before the first video. |
| `video_onset` | On the screen flip showing the first available decoded video frame. |
| `video_offset` | On the screen flip clearing the video after it ends. |
| `pause` | On entering the pause function, including between-block waits. |
| `attgrabber` | Before playing the extra X-controlled video break; not flip-aligned. |
| `block_end` | After completing the block, including any requested final-video pause/break. |
| `block_stopped` | When the operator stops from an Esc pause within a block. |
| `study_end` | After normal completion of all blocks. |
| `study_stopped` | After an operator-requested stop, including between blocks. |

JSON events contain `time`, `trigger`, `block`, `trial`, and `video`. Time is in
seconds from just before `study_start`, including pauses but excluding setup.
Video events identify the block, trial, and filename. Eye tracking and webcam
receive only the event name and use their own recording clocks.

Scheduled attention clips use ordinary video onset/offset events; `attgrabber`
refers only to the extra X break. There is no separate `resume` event, and
aborting on the start screen emits no study start/stop event.

## Saved data

Under `Data/Sxxx/`:

- `Sxxx_sequence.csv`: the participant's assigned video order.
- `Sxxx_sequence.json`: the planned sequence and actual events, saved after each
  block and at session end. Use events to identify which videos actually played
  if the session stopped early; events since the last save may be lost on a crash.
- `Sxxx_gaze.h5`: gaze data and eye-tracker events, when enabled; gaze is saved
  after each movie.
- `video/`: optional webcam recording and timing files.
